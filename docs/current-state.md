# Текущее состояние Orion

Дата фиксации: 22 июля 2026 года.

## Подтверждённая схема входящего звонка

```text
Plusofon
→ Asterisk
→ контекст from-plusofon
→ Stasis(orion)
→ Node.js backend через ARI
→ создание Snoop-канала
→ создание mixing bridge
→ создание ExternalMedia с AudioSocket
→ подключение к TCP 127.0.0.1:9019
→ возврат основного канала в dialplan
→ Dial(PJSIP/sip6@bitrix24-out,60)
→ Bitrix24
```

## Подтверждённая схема исходящего звонка

```text
Bitrix24
→ контекст from-bitrix24
→ Dial(PJSIP/${EXTEN}@plusofon,60)
→ Plusofon
```

На текущем этапе Orion подключён только к входящим звонкам.

## Подтверждённые факты

- Backend находится в `/opt/orion-backend/orion.js`.
- Backend запускается вручную командой `node orion.js`.
- AudioSocket TCP-сервер слушает `127.0.0.1:9019`.
- Подключение к Asterisk ARI работает.
- Приложение `Stasis(orion)` получает основной входящий канал.
- Caller ID и идентификатор канала читаются через ARI.
- Основной канал успешно возвращается в dialplan через `continueInDialplan()`.
- После возврата основной канал уходит в Bitrix24 через `Dial()`.
- Snoop-канал успешно создаётся через ARI с прослушиванием обоих направлений.
- Snoop-канал входит в приложение Stasis.
- Mixing bridge успешно создаётся через ARI.
- ExternalMedia успешно создаётся с параметрами `transport=tcp` и `encapsulation=audiosocket`.
- Для AudioSocket передаётся обязательный UUID через параметр `data`.
- Snoop и ExternalMedia объединяются в одном bridge.
- Asterisk подключается к Node.js TCP-серверу на `127.0.0.1:9019`.
- Node.js фактически получает бинарные пакеты AudioSocket.
- Наблюдаемый размер пакета — 643 байта, что соответствует 3 байтам заголовка и 640 байтам полезной нагрузки.
- Основной звонок не блокируется работой дополнительного медиатракта.

## Подтверждающие логи

```text
[ARI] StasisStart
[ARI] Имя канала: PJSIP/plusofon-...
[ARI] Snoop-канал создан: ...
[ARI] Bridge создан: ...
[ARI] ExternalMedia создан: ...
[ARI] Snoop добавлен в bridge: ...
[ARI] ExternalMedia добавлен в bridge: ...
[ARI] Аудиотракт создан: Snoop → Bridge → ExternalMedia → AudioSocket
[AudioSocket] Подключение: ...
[AudioSocket] Получено 643 байт
[AudioSocket] Получено 643 байт
```

## Пока не реализовано

- Буферный разбор бинарного протокола AudioSocket.
- Разделение служебных пакетов, UUID и аудиопакетов.
- Извлечение чистого PCM из полезной нагрузки.
- Сохранение тестового PCM/WAV для проверки качества звука.
- Передача аудио в STT.
- Потоковая транскрибация.
- LLM-анализ разговора.
- Подсказки менеджеру в карточке Bitrix24.
- Поддержка исходящих звонков в Orion.
- Очистка bridge и дополнительных каналов после завершения каждого звонка полностью не проверена.
- Автозапуск backend через systemd или PM2.

## Следующий инженерный шаг

Реализовать корректный буферный парсер протокола AudioSocket.

Критерий успеха:

```text
[AudioSocket] Тип пакета: аудио
[AudioSocket] Полезная нагрузка: 640 байт
```

После этого сохранить несколько секунд PCM в файл и проверить, что в нём действительно слышен разговор без повреждений и смещения границ пакетов.
